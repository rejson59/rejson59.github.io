# Powiadomienia RejChat

Dzwonek obok konta we wspólnym nagłówku strony pokazuje nowe polubienia i komentarze do własnych wpisów oraz odpowiedzi na własne komentarze. Zdarzenia powstają od instalacji migracji `supabase/2026-11-02_rejchat_notifications.sql`; starych zdarzeń nie dopisujemy wstecz. Nie powstają powiadomienia o własnych działaniach. Cofnięcie polubienia usuwa powiązane powiadomienie, podobnie usunięcie komentarza lub wpisu.

Skrzynka i stan odczytu są po stronie serwera, dostępne wyłącznie po weryfikacji tokena sesji; lista pokazuje 50 najnowszych zdarzeń, a licznik obejmuje wszystkie nieprzeczytane. Kliknięcie powiadomienia z dowolnej podstrony prowadzi do RejChat. Link otwiera właściwy wpis nawet wtedy, gdy jest poza ostatnimi 40 wpisami. Oznaczenie wszystkich działa także dla starszych zdarzeń. W aktywnej karcie lista jest odświeżana co 30 sekund, po powrocie do karty i po otwarciu panelu. To nie są systemowe powiadomienia push — zamknięta strona ich nie wyświetla. Istniejący dzwonek strony głównej dotyczący projektów, zgłoszeń i obecności pozostaje osobny.

Tabele nie mają bezpośrednich uprawnień dla `anon` ani `authenticated`, mają włączone RLS, a funkcje sprawdzają właściciela. Mechanizm nie pobiera ani nie przechowuje treści prywatnych wiadomości. Błąd wyzwalacza jest logowany i nie blokuje publikacji komentarza ani reakcji. Usuwanie użytkownika i wpisu działa poprzez kaskadowe klucze obce. Powiadomienia nie mają automatycznej retencji i wraz z rozwojem serwisu należy monitorować ich liczbę.

Testy: `scripts/jsdom/shared-notifications.browser.js`, `scripts/jsdom/rejchat-notifications.browser.js` (Chromium, mock HTTP) oraz transakcyjny test SQL na przygotowanym środowisku (`supabase/tests/rejchat_notifications.sql`). Testy przeglądarkowe nie potwierdzają działania produkcyjnego HTTP/CORS.
