# RejSejf

Prywatna przestrzeń pod `/rejsejf` korzysta z istniejącego konta Rejson, nie z Supabase Auth. Zalogowany właściciel może tworzyć, odczytywać, edytować i usuwać zwykłe tekstowe notatki oraz dodawać, pobierać i usuwać pliki. Nie ma publicznych linków ani automatycznego terminu wygaśnięcia. Przy zmianie konta interfejs natychmiast usuwa poprzednie dane; ponowny zapis edytowanej notatki sprawdza wersję, aby nie nadpisać zmiany z drugiego urządzenia.

Tabele są chronione RLS, bez dostępu `anon` i `authenticated`; funkcje `SECURITY DEFINER` ustalają właściciela wyłącznie przez `community_session_user(p_token)` i ograniczają każdą operację do tego konta. Token jest wysyłany w treści żądania, nie w URL. Pliki są przechowywane jako `bytea` w bazie, bez publicznego bucketa. Limit: 5 MiB na plik, 100 KiB na notatkę, 25 MiB i 200 elementów na konto, 150 MiB wspólnie. Zapis i usuwanie synchronizują się zamkiem transakcyjnym, dzięki czemu równoczesne zapisy nie obchodzą limitów. Liczby dotyczą danych logicznych, a nie kosztu rzeczywistego magazynu, kopii i WAL; należy monitorować plan bazy.

To nie jest szyfrowanie end-to-end ani archiwum z gwarancją kopii: administrator bazy może odczytać treść, a dostęp zależy od bezpieczeństwa konta. Starszy PIN jest słabszy od hasła. Nie przechowywać tu haseł i bardzo wrażliwych danych. Przy usunięciu konta dane są usuwane kaskadowo, o ile inne zależności konta nie uniemożliwiają usunięcia. Na stronie nie uruchamiamy pigułki zgłoszeń ani nagrywania: zawartość sejfu nie powinna trafiać do załączników. `data-rj-private` dodatkowo wyłącza ją z migawek DOM. Znaczniki w HTML zabezpieczają przed wstrzyknięciem tych skryptów przez starsze wersje service workera.

Migracja: `supabase/2026-11-04_rejsejf.sql`. Test SQL `supabase/tests/rejsejf.sql` wykonuje się w transakcji i kończy `rollback`. Test interfejsu: `cd scripts/jsdom && npm install && node rejsejf.test.js`; test Chromium: `CHROME_BIN=… node rejsejf.browser.js` (backend w obu testach jest mockowany). Migrację należy uruchamiać przed publikacją interfejsu; po DDL warto przeładować schemat PostgREST (`notify pgrst, 'reload schema'`).
